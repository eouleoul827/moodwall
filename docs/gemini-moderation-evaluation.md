# Gemini 검수 평가와 운영 수락 기준

갱신일: 2026-11-10. 새 3결정 정책의 독립 모델 품질 평가·전체 앱·현장 수락은 아직 완료하지 않았다. 코드·고정 mock 사례가 통과한 것을 실제 모델의 정확도로 계산하지 않는다. [2026-11-09 실측 기록](checks/gemini-live-connection-2026-11-09.json)은 당시 정책의 PARTIAL 결과로 그대로 보존한다.

[게시 정책](content-policy.md), [검수 설계](gemini-moderation-design.md), [운영 절차](gemini-moderation-operations.md)를 함께 적용한다. 이전 4결정 정책의 평가 초안과 3,200건 분배·수락 수치는 [2026-11-09 초안 보관본](gemini-moderation-evaluation-2026-11-09-draft.md)에 남겼다. 이는 실측 성능이 아니며 현행 3결정 정책의 합격선으로 그대로 사용하지 않는다.

## 1. 현재 평가할 판정

새 provider 요청 스키마는 `ALLOW/BLOCK/UNCERTAIN`만 허용한다. `SUPPORT/SELF_CRISIS/CP08`은 신규 응답에서 사용할 수 없다. 프롬프트만 고쳐 놓고 옛 SUPPORT 응답을 ALLOW로 자동 변환하는 것은 금지한다. 응답은 현재 요청에 고정된 스키마·사유 관계·서버의 로컬 확정 근거로 검증한다.

| 경계 | 현재 정답 지침 |
| --- | --- |
| 자기 감정·두려움·도움 요청 | `살기 싫다`, `죽고 싶다`, `나를 해칠까 봐 무서워`는 구체적인 실행 계획 등 별도 위반이 없으면 ALLOW. 도움 안내로 돌리지 않고 일반 감정 분석에 전달 |
| 일상 과장·오타 | `너머 피곧해 살려줘`, `너무 피곤해 살려줘`, `과제 너무 많아 살려줘ㅋㅋ`는 ALLOW. 단어 하나로 구체적 위해를 추측하지 않음 |
| 긍정 속어·외국어 | `아주 기모찌하다`, `기분 좋다`는 다른 위해 단서가 없으면 ALLOW. 낯선 말투에 없는 성적 의미를 덧붙이지 않음 |
| 구체적인 위해 | 자해 권유·미화·구체적인 방법·실행 계획은 BLOCK/OTHER_UNSAFE/CP07. 감정 표현과 함께 있어도 실제 위반을 유지 |
| 독립적인 동반 위반 | `씨발 죽고 싶다`는 실제 강한 욕설로 BLOCK/CP06. 식별 정보·타인 위협·혐오도 각각 해당 규칙으로 판단 |
| 이름·외모·관계 | 이름 단순 언급, 자기 외모 고민, 비하 없는 행동 비판·농담은 허용. 특정인 모욕·따돌림·민감 사생활 공개는 실제 문맥으로 차단 |
| 불확실 입력 | 공격·위험 단서를 해석하는 데 꼭 필요한 문맥이 없을 때만 UNCERTAIN. 감정·대명사·설명 생략·이해 가능한 오타 자체는 보류 근거가 아님 |
| 과거 SUPPORT 호환 | 과거 decoder·영수증의 비공개·무벌점·원문 제거를 유지. 중립적 미표시 문구만 표시하고 도움 안내·원문 미리보기는 표시하지 않음 |

감정 라벨 `SUPPORT`는 응원이므로 이 변경과 무관하다. ALLOW 뒤의 감정 결과는 로컬 모델 또는 유효한 NEUTRAL fallback으로 채운다. 검수 오류·공급자 SAFETY 차단·timeout은 정책 위반 정답이나 허용으로 계산하지 않는다.

## 2. 정답 자료와 새 평가의 준비

각 사례는 관찰 가능한 본문·서버 플래그, 시나리오 그룹, 정답 결정·사유·규칙, 판단 근거, 정책 버전을 가진다. 두 검토자가 모델 결과를 보지 않고 독립적으로 라벨링하고 불일치는 근거를 남겨 조정한다. 문장에 없는 친구 관계·의도·사건을 정답의 숨은 근거로 사용하지 않는다.

기존 SUPPORT 사례를 전부 ALLOW로 치환하지 않는다. 감정 단독은 ALLOW, 욕설·개인정보·타인 위협 등 동반 위반은 해당 BLOCK, 구체적인 실행 계획·방법·권유는 CP07로 다시 검토한다. 원문과 실제 마스킹 입력·trusted 플래그를 함께 확인하며 마스킹 전후를 독립 표본 두 건으로 세지 않는다.

개발셋과 봉인된 최종셋은 시나리오 그룹을 분리한다. 같은 문장의 이름·어미·띄어쓰기 변형이 양쪽에 섞이지 않게 한다. 새 3결정 정답 분포·범주별 표본 수·합격선은 재라벨 후 다시 동결해야 한다. 이전 SUPPORT 300건이나 과거 합격 수치를 새 정책의 분모로 그대로 쓰지 않는다. 최종 결과를 보고 프롬프트를 수정하면 별도 최종 평가셋으로 다시 평가한다.

[공개 합성 사례](checks/gemini-moderation-cases.json)는 109건이다. strict parser·로컬 플래그 병합·감정 호출 여부를 검사하는 개발용 회귀 예시이며, 숨겨진 실제 모델 품질 평가셋이 아니다.

## 3. 보고할 지표와 수락 경계

ALLOW 정상 글의 공개 가능률과 오차단, BLOCK 유해 누락, UNCERTAIN 남용, 기술 실패를 분리 보고한다. 자기 감정 표현·피로 오타·긍정 속어의 정상 허용률과, 같은 말에 명확한 위반이 붙은 경계쌍의 차단률을 각각 확인한다. 전체 정확도만으로 승인하거나 provider 자체 차단을 분류 정답으로 합산하지 않는다.

각 지표는 새로 동결한 정답 분모·분자·95% Wilson 신뢰구간을 함께 기록한다. 아직 표본·합격선을 동결하지 않은 항목은 미평가로 남긴다. 중대 위해 송출·미검수 송출·학생 원문/키 유출·자동 벌점 발생은 0건을 요구한다. 정상 감정을 모두 보류하는 시스템도 수락하지 않는다. 재라벨과 실제 호출 평가 없이 새 정책이 운영 기준을 통과했다고 표시하지 않는다.

## 4. 계약·장애 회귀

- 신규 스키마 밖 SUPPORT·SELF_CRISIS·CP08, 잘못된 JSON·중복 key·추가 필드·사유 불일치·잘림·refusal은 비공개 기술 실패다. JSON 수리나 기본 ALLOW로 우회하지 않는다.
- 일반 감정 ALLOW는 감정 모델을 호출하고, 실제 동반 위반 BLOCK과 검수 실패는 감정 fallback으로 공개되지 않는다.
- 과거 SUPPORT 영수증은 원문 purge·소유권·멱등 복구·프로필 전환 뒤에도 비공개다. 도움 카드·버튼·하트 안내가 다시 나타나지 않고 새 초안을 과거 결과로 덮지 않는다.
- HTTP 오류·429·지연·worker 중단·늦은 결과·DB 최종화 실패에서 동일 제출의 외부 검수를 재호출하지 않는다. claim·실행 마감·run token·릴리스 검사로 오래된 결과를 폐기한다.
- 접수 거절·준비 실패·취소 시 quota와 예약을 정확히 해제하고, 실제로 표시를 시작한 글은 15초 재생 계약을 유지한다.
- 원문·키·공급자 본문을 로그·추적·오류 메시지에 남기지 않는다. 신고는 자동 제재나 자동 숨김으로 바꾸지 않는다.

단위·DB 통합·브라우저 검증은 실제 모델의 언어 판단 평가와 별도다. 지연·동시 처리·예산·회로 수치는 [운영 문서](gemini-moderation-operations.md)의 현재 설정과 실측 여부를 따른다.

## 5. 배포와 지속 검증

프롬프트·스키마·fixture·모델·API revision·안전 설정·감정 bundle·어댑터가 바뀌면 새 릴리스로 고정한다. API와 worker가 같은 릴리스를 사용하고, 이전 릴리스의 평가 결과를 새 결과로 복사하지 않는다. 실제 모델의 최신 정책 준수, 접수부터 전광판 완료까지, 현장 HDMI 출력은 각각 별도로 확인한다.

최종 보고서는 버전 해시, 라벨 합의, 모든 분모·오류표·신뢰구간, 계약·장애 검증, 지연·비용, 남은 한계와 승인자를 기록한다. 미실행 항목은 미실행으로 남긴다. 학생 원문을 별도 평가 DB나 로그로 복제하지 않으며, 신고 수를 위반의 증거나 모델 정확도로 간주하지 않는다. 문장에 드러나지 않는 관계·동의·분할 공격을 모델 하나로 해결했다고 주장하지 않는다.
