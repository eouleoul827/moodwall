# 검증 기준

설계의 계약, DB 제약, AI 연결, 권한과 복구를 아래 상황으로 검증합니다. 문서가 존재하는 것과 서비스가 검증된 것은 다릅니다. 현재 앱 구현 전이므로 HTTP 런타임, 실제 요청 동시성, 학습 모델, 배포 시험은 아직 실행하지 않았습니다. 문서 명세와 실제 PostgreSQL의 스키마·일부 제약 검사는 아래 실행 기록으로 구분합니다.

## 자동 검사 범위

PR마다 코드가 생긴 영역의 타입, 포맷, 단위 검사와 빌드를 수행합니다. PostgreSQL 트랜잭션과 동시성은 실제 PostgreSQL 통합 시험으로 확인합니다. SQLite 대체 시험만으로 잠금 동작이 검증되었다고 하지 않습니다. AI 시험은 고정 fixture와 실제 평가셋을 분리합니다.

OpenAPI 문서는 JSON 형식, 내부 참조, 파라미터, 예시와 상태 enum을 확인하고 구현 이후 실제 생성 명세와 비교합니다. SQL 문법 검사나 빈 DB 적용은 V05~V13 같은 경쟁 상황 시험을 대신하지 않습니다.

정적 계약과 DDL의 재현 명령은 [설계 검사](checks/README.md)에 있습니다. formatter·타입·앱 통합·프론트 build 등 실제 CI 검사 이름과 릴리스 수락 조건은 [운영 실행 기준](delivery-and-operations.md)을 따릅니다. CI 설정이나 앱 테스트가 이미 구현되었다는 뜻은 아닙니다.

[전체 분기표](backend-completeness-tree.md)의 102개 항목은 구현 수락 조건이고, 위 60개 시험은 관련 항목을 묶은 출시 시나리오입니다. 숫자가 많다는 이유로 모든 보안·장애 상황이 증명되지는 않습니다. API 27개의 operationId 매핑 누락은 정적 검사로 찾으며 실제 HTTP 동작은 별도로 확인합니다.

## 문서 검토 범위

QR와 세션 권한, rolling 사용량, 당일 제재, AI 결과, 표시 상태, 운영 권한은 서로 다른 문서에서 같은 이름과 정책을 사용해야 합니다. 최근 60분의 승인·미확정 상태가 한도 이내인지 진단하며 중복 카운터는 두지 않습니다. 확인 결과는 작업 마지막에 실제 실행한 범위만 기록합니다.

최신 정책은 **승인 즉시 일반 떠다니는 말풍선**이며4개 자리·강조·표시 대기는 없습니다. DB 원문은 접수 1시간, 받은 글은이후내용담긴투명 말풍선으로다음 KST 자정까지남습니다. 승인 5개이상/100개초과목록전체 페이지·동시숨김·커서변조/만료/세대/날짜·역순응답·중복ID를확인합니다. 정확한 1시간 DB/API제외와로컬 AMBIENT전환, 자정·숨김·reset·기기 세대·인증 전 미복원·저장 실패도시험합니다. 과거 251/226개는변경 전이력이며이번정책검증을대신하지않습니다. 작은 배치 DELETE·중단/오프라인미연장·제재/쿼터·삭제후키재사용을회귀합니다.
