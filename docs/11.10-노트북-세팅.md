# 11.10 노트북 세팅

작성: 2026-11-10. 도서관 노트북(Windows 10/11)에 무드월 서버와 LED 전광판(2046×768)을 처음 설치하는 절차다. 노트북에 연결한 코딩 에이전트(Codex 등)와 사람이 같이 보도록 썼다. 각 단계에 누가 하는지 표시했다.

- **[사람]**: GUI 클릭, 웹 로그인, 비밀값 입력. 에이전트는 사람에게 요청하고 끝났는지 확인만 한다.
- **[에이전트]**: 에이전트가 실행할 수 있는 명령이다. 실행 뒤 "확인" 항목으로 결과를 검증한다.

배경 설명은 [library-laptop-operation.md](library-laptop-operation.md)에 있다. 이 문서는 실행 순서만 다룬다.

이번 설치는 **Gemini 검수 + 로컬 감정 모델**을 함께 사용한다. GitHub에서는 코드만 받고, 아래 감정 모델 폴더는 따로 옮긴다. 설치 완료는 프로그램 실행 여부가 아니라 4.4의 AI 준비 확인과 6절의 실제 송출 시험으로 판단한다. 설치·운영자 점검 중에는 전광판 패널을 꺼 둔다. 현재 직원용 시작 창의 상태·오류 안내는 패널에 보일 수 있다.

## 에이전트 규칙 (반드시 지킬 것)

1. **비밀값을 출력하거나 기록하지 않는다.** 대상은 `.env`의 내용, `MOODWALL_GEMINI_API_KEY`, DB 비밀번호, 운영자 비밀번호, Tailscale 인증 키다. 로그, 커밋, 채팅 어디에도 남기지 않는다.
   - `.env`는 통째로 `cat`/`Get-Content` 하지 않는다. 확인이 필요하면 키 이름만 본다. 예: `Select-String .env -Pattern '^MOODWALL_PUBLIC_ORIGIN='`
2. **`.env`는 커밋하지 않는다.** 이미 `.gitignore`에 있다. 개발 PC의 `.env`를 복사해 오지 않는다.
3. **Gemini 키는 사람이 직접 입력한다.** `setup_gemini.py`가 숨김 입력으로 묻는다. 에이전트가 키를 인자나 환경변수로 넘기지 않는다.
4. 관리자 권한이 필요한 명령은 표시해 두었다. 권한이 없으면 사람에게 관리자 PowerShell에서 실행해 달라고 요청한다.
5. 저장소의 코드, 설정, 이 문서를 고치는 것은 이번 설치 범위가 아니다. 문제가 보이면 고치지 말고 사람에게 보고한다.
6. 각 단계의 "확인"이 통과하지 않으면 다음 단계로 넘어가지 않는다.

## 0. 준비물 [사람]

- Tailscale 무료 계정(Google 로그인). 공개 주소의 주인이 되므로 인수인계할 사람을 정해 둔다.
- Gemini API 키: 이미 받은 키, 개발 PC `.env`의 `MOODWALL_GEMINI_API_KEY` 값이다. 결제가 연결된 계정의 키여야 한다(무료 등급은 입력 내용이 Google 서비스 개선에 쓰일 수 있다).
- 노트북 관리자 비밀번호, 직원이 쓰는 Windows 계정 이름.
- LTE 휴대폰. 바깥 접속은 학교 Wi-Fi가 아니라 LTE로 확인한다.
- 감정 모델 폴더 `student-v0` 전체(약 512 MB): 개발 PC의 `C:\mood project\moodwall\models\student-v0`. USB 등으로 따로 옮긴다. `.env`, DB 데이터, 가상환경은 이 폴더에 포함되지 않으며 복사 대상도 아니다.

**4.0 [사람이 복사, 에이전트가 확인]** 준비물의 `student-v0` 폴더를 새 노트북의 `C:\moodwall\models\student-v0`에 복사한다. 압축해서 옮겼다면 압축을 푼다. 폴더가 두 번 중첩되지 않게 확인한다.

```text
C:\moodwall\models\student-v0\
  manifest.json
  config.json
  tokenizer.json
  tokenizer_config.json
  model.safetensors
```

Git에서 모델 가중치는 내려오지 않는다. 다음은 저장소에 기록된 모델과 복사한 파일이 일치하는지 확인한다. Python AI 라이브러리 설치나 API 호출 없이 실행할 수 있다.

```powershell
cd C:\moodwall
& {
    $ErrorActionPreference = 'Stop'
    $bundle = 'C:\moodwall\models\student-v0'
    $expected = Get-Content '.\docs\models\student-v0-manifest.json' -Raw -Encoding UTF8 | ConvertFrom-Json
    $actual = Get-Content (Join-Path $bundle 'manifest.json') -Raw -Encoding UTF8 | ConvertFrom-Json
    if ($actual.model_bundle_version -ne $expected.model_bundle_version) { throw '모델 버전이 다릅니다. 담당자에게 확인해 주세요.' }
    foreach ($name in @('config.json', 'tokenizer.json', 'tokenizer_config.json', 'model.safetensors')) {
        $hash = (Get-FileHash -LiteralPath (Join-Path $bundle $name) -Algorithm SHA256).Hash.ToLowerInvariant()
        if ($actual.artifacts.$name -ne $expected.artifacts.$name -or $hash -ne $expected.artifacts.$name) { throw "모델 파일 확인 실패: $name" }
    }
    Write-Output 'PASS: 감정 모델 4개 파일의 체크섬이 일치합니다.'
}
```

실패하면 다시 복사하거나 모델 담당자에게 확인한다. 서버가 시작할 때 구조·라벨·불필요한 추가 파일도 별도로 검증한다. 파일 이름이나 manifest를 임의로 고쳐 통과시키지 않는다.

**4.1 [사람이 입력, 에이전트가 실행 가능]** 첫 설정을 한다. 이 명령은 대화형이라, 에이전트가 숨김 입력을 대신할 수 없으면 사람이 직접 실행한다.
```powershell
python scripts/setup_gemini.py --emotion-model "C:\moodwall\models\student-v0" --start --create-operator --operator-name admin
```
- `Gemini API key (hidden):`에서 **사람이** 키를 붙여 넣는다.
- 이어서 운영자 `admin`의 비밀번호를 두 번 입력한다. 이것도 사람이 한다.
- 이 명령이 하는 일: `.env` 생성(새 비밀값 자동 생성), 화면 빌드(`npm ci`, `npm run build`), DB 마이그레이션, 전광판 초기화, 운영자 생성, 개발 구성으로 시작.
- 감정 모델 경로도 `.env`의 `MOODWALL_EMOTION_BUNDLE_DIR`에 저장한다. API는 모델 파일을 검증하고, worker가 CPU에서 감정을 분류한다. 첫 설치는 이미지 다운로드·빌드 때문에 오래 걸릴 수 있다. 시작 시 합성 문구로 Gemini 연결을 확인하므로 소량의 API 사용료가 발생할 수 있다.

**4.2 [에이전트]** `.env`의 `MOODWALL_PUBLIC_ORIGIN` 한 줄만 `<ORIGIN>`으로 바꾼다. 다른 줄은 건드리지 않는다.
```powershell
$origin = 'https://moodwall-library.<tailnet>.ts.net'   # 3의 실제 값
$path = 'C:\moodwall\.env'
$lines = [IO.File]::ReadAllLines($path)
if (-not ($lines -match '^MOODWALL_PUBLIC_ORIGIN=')) { $lines += "MOODWALL_PUBLIC_ORIGIN=$origin" }
$lines = $lines -replace '^MOODWALL_PUBLIC_ORIGIN=.*$', "MOODWALL_PUBLIC_ORIGIN=$origin"
[IO.File]::WriteAllLines($path, $lines, (New-Object Text.UTF8Encoding($false)))
Select-String $path -Pattern '^MOODWALL_PUBLIC_ORIGIN='
```

**4.3 [에이전트]** 도서관 구성(운영 모드)으로 다시 시작한다.
```powershell
cd C:\moodwall
docker compose -f compose.yaml -f compose.frontend.yaml -f compose.gemini.yaml -f compose.gemini-emotion.yaml -f compose.library.yaml up -d --build api worker
docker compose -f compose.yaml -f compose.frontend.yaml -f compose.gemini.yaml -f compose.gemini-emotion.yaml -f compose.library.yaml ps
```

**확인**
- `ps`에서 `api`가 `healthy`, `worker`와 `db`가 `running`이면 통과.
- 에이전트가 `Invoke-WebRequest "$origin/api/health/live" -UseBasicParsing`을 실행해 200이 나오면 통과.
- **[사람]** LTE 휴대폰으로 `<ORIGIN>/operator`를 열고 `admin`으로 로그인한다. 처음에는 공개까지 최대 10분 걸릴 수 있다.
- 운영 모드는 `MOODWALL_PUBLIC_ORIGIN`이 https가 아니면 api가 시작을 거부한다. api가 계속 재시작하면 `docker compose ... logs api --tail 50`을 보되, 비밀값이 섞인 줄은 출력하지 않는다.

**4.4 [사람과 에이전트] AI 준비 확인 — 접수 재개 전에 필수**

`healthy`, `running`, `/api/health/live` 또는 `/api/health/ready`의 200만으로 AI 준비가 끝났다고 판단하지 않는다. 감정 모델 적재와 Gemini 연결 확인이 추가로 필요하다.

1. 운영자 화면의 **자동 검수**가 **검수 가능**이고 오류 안내가 없는지 확인한다. **모의 검수**, **연결 확인 중**, **검수 중단됨**, **복구 확인 중**이면 아직 통과가 아니다. 운영자 화면은 보이는 동안 약 15초마다 상태를 갱신한다.
2. 기술 확인이 필요하면 **운영자로 로그인한 같은 브라우저**에서 `<ORIGIN>/api/operator/moderation/provider`를 연다. 응답 최상위에서 `enabled=true`, `profile="gemini"`, `transportConfigured=true`, `syntheticAccounting=false`, `workerReady=true`, `mode="OPEN"`, `lastFailureCode=null`을 모두 확인한다. 인증 쿠키나 비밀번호를 채팅에 붙이지 않는다. 로그인되지 않았다면 401이 정상이다.
3. 이 상태 조회 자체는 Gemini를 호출하지 않는다. worker의 준비 상태는 현재 배포의 모델 적재·초기 확인과 실제 Gemini 합성 문구 연결 확인을 통과한 뒤에만 생긴다. **4.3의 감정 모델 override를 포함한 구성인지도 함께 확인**한다. 모델 없이 실행한 worker도 준비 상태가 될 수 있기 때문이다.
4. 감정 모델을 쓰는 worker는 기동 예산이 360초다. `up` 이후 약 6분이 지나도 준비되지 않으면 계속 재시작하지 말고 원인을 확인한다. `PROVIDER_AUTH_ERROR`는 키·프로젝트 권한, `PROVIDER_RATE_LIMITED`는 사용 한도, `PROVIDER_TARIFF_EXPIRED`는 코드의 사용료 기준 갱신이 필요하다. 모델 파일 오류·메모리 부족·학교망 차단도 확인한다. 원시 로그나 `.env` 전체를 공유하지 않는다.

이 확인은 설치 준비 점검이다. 실제 휴대폰 제출·감정 색·전광판 표시·아이콘 재시작은 6절에서 별도로 시험한다. 확인 전까지 접수·송출 일시정지를 유지한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\moodwall\ops\display-launcher\Install.ps1" -ServerRoot "C:\moodwall" -WithEmotionModel -PlanOnly

```
- `-WithEmotionModel`은 4.3과 같은 5개 Compose 파일 목록을 직원 런처의 `server.json`에 저장한다. 다음 날 **무드월 켜기**에도 감정 모델 설정이 유지된다. `-PlanOnly` 결과의 `Server.composeFiles`에 `compose.gemini-emotion.yaml`이 있는지 확인한다. 이 옵션은 모델 파일을 복사하거나 이미지 빌드를 대신하지 않는다.
- 설치 도구는 다음 경우 이유를 한국어로 출력하고 종료 코드 1로 끝난다. 이유를 사람에게 그대로 전달한다.
  - `.env` 주소가 이 노트북의 Tailscale 주소와 다르다.
  - Tailscale이 로그인되어 있지 않다.
  - Funnel이 꺼져 있다.
  - `frontend/dist`가 없다.
- 성공하면 바탕화면에 **무드월 켜기**, **무드월 끄기**, **무드월 직원 설정·점검**이 생긴다.

5.5 전광판 등록 [사람]
1. **무드월 켜기**를 누른다. 로고만 보이면 정상이니 `Alt + F4`로 닫는다.
2. **무드월 직원 설정·점검** → **등록·설정 열기**를 누른다.
3. 휴대폰 `<ORIGIN>/operator`에서 등록 코드를 발급해 노트북에 입력한다.
4. 4.4의 AI 준비가 통과한 상태에서 운영자 화면의 **접수 재개**와 **송출 재개**를 누른다.
5. 설정 창을 닫고 **무드월 켜기**를 다시 누른다.

장치 등록은 사용하는 동안 자동으로 연장된다(마지막 사용 후 180일). 180일 넘게 안 켰거나 운영자가 해지했을 때만 다시 등록한다.

## 7. 문제 해결

| 증상 | 확인 순서 |
| --- | --- |
| 아이콘 설치가 Tailscale 때문에 실패 | `tailscale status`(로그인), `tailscale funnel status`(on, 127.0.0.1:8000), `.env`의 `MOODWALL_PUBLIC_ORIGIN`과 `Self.DNSName` 일치 여부 |
| 휴대폰에서 주소가 안 열림 | Docker Desktop 실행 여부 → `compose ps` → `tailscale funnel status` → 처음이면 10분 대기 |
| 켜기에서 "Tailscale이 꺼져 있어요" | 사람이 Tailscale 아이콘 → Connect. 반복되면 Run unattended 설정과 key expiry 확인 |
| 글이 계속 검수 대기 | worker 로그의 Gemini 연결 오류, 학교 웹필터 |
| 아이콘으로 다시 켠 뒤 감정 색이 모두 차분함 | `-WithEmotionModel`로 설치했는지, 모델 폴더와 `MOODWALL_EMOTION_BUNDLE_DIR` 경로가 맞는지 확인. 단일 문장의 중립 결과만으로 고장이라고 판단하지 않음 |
| 전광판에 로고만 | 직원 설정·점검 → 진단. 장치 해지·만료면 5.5 재등록 |
| api가 계속 재시작 | 운영 모드 시작 조건: `MOODWALL_PUBLIC_ORIGIN`이 https, 분석기가 `fake`가 아님(Gemini 설정 완료), `MOODWALL_SECRET_KEY`·`MOODWALL_QR_KEY`가 `change-`로 시작하지 않음. 4.1을 끝까지 했는지 확인 |

## 8. 직원용 안내 (출력해서 노트북 옆에)

**출근할 때**
1. 노트북을 켜고 로그인합니다.
2. 1~3분 기다리면 전광판에 무드월이 나옵니다.
3. 안 나오면 바탕화면의 **무드월 켜기**를 두 번 누릅니다.

**퇴근할 때**
1. 바탕화면의 **무드월 끄기**를 두 번 누릅니다.
2. "이제 노트북을 꺼도 괜찮아요"가 나오면 노트북을 끕니다.

**이럴 때는**
- "Tailscale이 꺼져 있어요": 오른쪽 아래 Tailscale 아이콘 → **Connect** → **무드월 켜기**를 누릅니다.
- "무드월을 켜지 못했어요": 노트북을 다시 시작하고 **무드월 켜기**를 누릅니다. 그래도 안 되면 담당자에게 알립니다.
- 로고만 계속 보이면: **무드월 끄기** → **무드월 켜기**를 누릅니다. 10분 뒤에도 그대로면 담당자에게 알립니다.
- 이상한 글이 보이면: 담당자에게 알립니다.

**하지 말아 주세요:** 전광판 위에 다른 창 띄우기, 브라우저 데이터 지우기, 프로그램 삭제, 덮개를 닫아 치우기.

설치 담당자의 바탕화면에 있는 `무드월 도서관 설치 안내.docx`는 이전 출력본일 수 있다. 감정 모델 연결·AI 준비 확인·아이콘 명령은 이 Markdown의 최신 절차를 우선한다. 이번 보완에서 Word 파일은 갱신하지 않았다.
