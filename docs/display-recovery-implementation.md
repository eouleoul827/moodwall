# 전광판 오류 비노출과 복구 구현

2026-11-05. [오류 비노출 설계](display-recovery-design.md)의 공개 화면·직원 설정·진단·재생 복구를 코드에 반영했다. HTTP 계약은 **0.11.0**, DB head는 **0008_display_diagnostics**다. 배포 전에 기존 DB에 migration을 적용하고 서버와 프론트 빌드를 함께 갱신한다. DB·장치 쿠키·전용 브라우저 프로필을 초기화하지 않는다.

## 공개 화면과 직원 사용

- `/display`는 공개 송출 전용이다. 초기 연결·미등록·인증 만료·연결 오류·렌더 오류에 등록 폼이나 오류 안내를 표시하지 않고 같은 색·로고의 기본 배경을 유지한다. 유효하지 않은 QR과 스캔 안내도 함께 가린다.
- `/display/setup`은 직원이 명시적으로 연다. 기존 일회용 코드·만료 쿠키 정리·CSRF 갱신·페어링 응답 유실 복구를 유지했다. 설정 화면은 재생 claim과 heartbeat를 실행하지 않는다.
- 투명 말풍선도 동일 프로필의 직원 설정에서 선택해 기존 운영자 숨김 화면으로 이동한다. 목록 조회는 저장소를 쓰지 않으며, 숨김 실행은 운영자 인증을 요구한다.
- 같은 장치 자격의 세션 재조회는 진행 중인 재생 엔진을 재시작하지 않는다. 실제 자격 변경은 새 인증 문맥으로 검증한다. 직원 설정이나 아이콘 실행으로 운영자 PAUSED와 접수 중단을 해제하지 않는다.
- 공개 런처는 실패 팝업을 띄우지 않는다. 별도 직원 설정·점검 아이콘으로 등록·재연결·진단을 처리한다. 기존 공개 시작 아이콘과 프로필·쿠키를 보존한다. [설치와 사용법](../ops/display-launcher/README.md)을 따른다.

복제 화면에서는 직원 설정도 전광판에 보이므로 패널을 끄고 설정한다. 직원용 브라우저를 닫은 뒤 공개 시작 아이콘을 사용한다. 현재 런처는 직원 창이 열려 있으면 그 창을 공개 창으로 활성화하지 않는다. 실패한 공개 화면은 직원이 명시적으로 다시 열 수 있다.

## 재생과 보관 보존

준비 완료 순서·단일 재생 주체·정상 15초 하한·동일 명령 완료 복구·최초 표시 시작(서버 승인) 시각 기준 1시간 원문 정리를 유지했다. 숨김·인증 만료·온라인 허가 만료·자정은 정상 재생 시간보다 우선한다.

빠른 일시정지→재개 사이에 서버 attempt가 INTERRUPTED가 되면 즉시 재생을 중단한다. 유효한 DONE 응답의 cacheScope를 검증해 완료 카드를 즉시 보관하므로 다음 snapshot이 실패해도 이미 받은 글을 보관할 수 있다. 이 완료 응답은 공개 표시 허가를 연장하지 않는다.

캐시 기본 상한은 5000개, 설정 최대는 10000개다. 변경·투명 전환 시점에만 정렬 결과를 갱신하고 매 프레임의 같은 view는 재사용한다. 4080개×한글·단일 이모지·복합 이모지의 저장·복구와 전체 반환을 검사했다. 브라우저 저장 용량을 넘으면 메모리를 유지하고 직원 진단을 남긴다. 실제 노트북의 4080개 DOM 애니메이션 성능은 별도 측정 대상이다.

서버 원문은 최초 표시 시작 승인부터 1시간 후 공급을 중단한다. 이미 받은 글은 같은 내용의 투명 말풍선으로 다음 KST 자정까지 보관한다. 원문 공급 종료와 로컬 캐시 삭제를 같은 동작으로 처리하지 않는다.

## 진단과 접수 복구

`POST /api/display/diagnostics`는 장치 인증·Origin·CSRF, 4KiB 입력, 고정 코드와 장치별 분당 10회 제한을 적용한다. 클라이언트 대기는 메모리 최대 20개·10분이고 같은 종류는 합산한다. 진단 실패가 재생을 멈추지 않는다. `GET /api/operator/display/diagnostics`는 운영자 인증 후 최신 상태를 보여 준다.

진단에는 학생 원문·이름·QR·자격·임의 예외 문자열을 넣지 않는다. 최신 상태와 최대 1000개 이력은 7일 정책으로 정리한다. heartbeat와 진단만으로 실제 패널 전원이 켜졌다고 판정하지 않는다.

학생 접수는 전송 전에 UUID 메타데이터만 sessionStorage에 저장하고, 새로고침 뒤 본인 영수증을 조회한다. 일반 503은 동일 키로 결과를 확인하며 새 UUID를 자동 발급하지 않는다. 게시 대기 10분과 실제 표시 시작 후의 기한을 반영해 polling하고 화면 복귀 때 다시 확인한다. 기존 완료 카드 형태는 유지한다. 신고의 인증 실패도 세션을 한 번 갱신해 같은 신고 UUID로 복구한다.

v2 장치가 확인된 전광판은 새 v1 접수를 거절하되, 전환 전 이미 접수한 동일 키의 재응답은 유지한다. production에서 정리 작업을 끈 설정은 시작 시 거절하며, Compose로 DB를 운영하면 재시작 정책을 적용한다.

세션·페어링의 성공 응답도 최소 필드 형식을 검증한다. 잘못된 JSON이나 HTML 응답을 장치 등록 성공으로 채택하지 않고 재조회한다. 429의 `Retry-After`는 HTML 오류 응답에서도 보존하며, focus·visibility·QR 변경 이벤트가 대기를 건너뛰지 않는다. 재생과 snapshot이 서로 다른 순서로 도착해도 장치 세대·revision을 비교해 오래된 응답으로 최신 일시정지를 해제하거나 새 15초 재생을 끊지 않는다.

## 검증 범위

- 최종 전체 React 검사 **89개·9개 파일 통과**. 공개 화면·직원 설정·진단·오류 경계·학생 접수와 신고 복구·지연 응답·429 대기를 포함한다. 가짜 시계로 재시도와 이벤트 순서를 검증하며 실제 노트북 성능 측정과 구분한다.
- 최종 `npm run build` 성공. Chrome 시각 확인 후 추가한 재시도·응답 검증 코드까지 빌드에 포함했다.
- 클라이언트 독립 모듈 전체 **140개 통과**. 그중 전광판 **99개**는 rapid pause·완료 ACK·숨김·재인증·자정·저장 실패·4080개 복구를 포함한다.
- Windows PowerShell 5.1 런처 **112개 검사 통과**. 실제 설치·브라우저 창 활성화·HDMI를 수행하는 검사는 아니다.
- Chrome 1920×1080에서 합성 401 응답을 사용해 공개 기본 배경을 시각 확인했다. 실제 학교 계정·학생 글·운영 서버는 사용하지 않았다.

테스트용 native PostgreSQL은 운영 데이터와 분리하며 실제 AI 키를 사용하지 않는다. 최초 전체 백엔드 실행은 693 passed·2 failed·13 skipped였다. skip은 실제 모델 번들 미설정 5건·Linux 전용 4건·Windows symlink 권한 4건이다. 두 실패는 DB 연결 대기와 큐가 감싼 DB timeout 응답 경로였으며, 일시적 큐 DB 오류는 503과 `Retry-After: 1`로 처리하도록 좁게 수정했다. 무결성·알 수 없는 큐 오류의 500과 트랜잭션 rollback은 유지한다. 수정 후 관련 재검증 결과는 아래 기록에 남긴다.

| 백엔드 검증 | 결과 |
| --- | --- |
| 최초 전체 실행 | 693 passed·2 failed·13 skipped |
| 수정 후 관련 13개 파일 재검증 | 120 passed·13 skipped·1 setup error. 기존 실패 두 경로와 신규 큐 오류 회귀 5개는 통과 |
| 위 setup error가 난 runtime 정책 파일 단독 재검증 | 4 passed. setup error는 운영자 로그인 준비 중 DB 연결 503으로, 제품 assertion 전 발생 |

검사 timeout을 늘리거나 실패 검사를 제외하지 않았다. 마지막 실행은 exit 0이고 검증용 PostgreSQL은 소유 PID·데이터 경로를 확인한 뒤 종료했다. 수정 후 전체 suite를 다시 한 번 연속 실행한 결과로 주장하지는 않는다. 로컬 상세 기록은 workspace `.local/display-recovery-503-regressions.log`와 `.local/display-recovery-final-runtime.log`에 있고, 저장소 `.local/display-recovery-frontend-final.log`·`display-recovery-build-final.log`·`display-recovery-node-final.log`에는 프론트와 독립 모듈 결과가 있다.

## 현장 검증과 AI 의존성

실제 웹주소로 설치·기기 등록·휴대폰 QR 입장·HDMI 출력·절전 복귀·재부팅·06:00~23:00 장시간 송출을 확인해야 한다. 앱의 첫 HTML조차 받지 못한 DNS·TLS·브라우저 자체 오류 화면까지 React가 숨기는 기능은 아니다. 로컬 기본 화면을 소유하는 별도 실행기는 현재 범위에 포함하지 않았다.

기존 Gemini 허용 결과 뒤 감정 predictor 연결과 모델의 실제 분류 품질 평가는 별도 AI 의존성이다. 이 전광판 복구 수정에서 감정 결과를 임의 생성하거나 검수 실패를 공개 허용으로 바꾸지 않았다. 실제 모델 평가와 생성형 배경 기능이 완성됐다는 뜻은 아니다.
