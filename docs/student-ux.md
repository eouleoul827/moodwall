# 무드월 학생 화면 최소 변경안

기준일: 2026-11-04. 학생에게 처리 과정을 세세하게 보여주지 않고 기존 HTML 시안의 작성·완료·경고 화면을 유지한다. [재생 설계](playback-design.md)의 상세 상태는 서버·운영·복구용이다. 학생 화면은 이 문서의 표현을 우선하며 현재 React 화면과 검증 범위는 [구현 현황](implementation-status.md)을 따른다.

## Gemini 비공개 지원 안내 추가 설계

[API 연결 전 검수 구현](gemini-moderation-implementation.md)에서 `reasonCode=SUPPORT_AVAILABLE`는 일반 `NEEDS_REWRITE` 안내보다 먼저 처리한다. 자신의 위기·도움 요청은 원문 미리보기와 수정 경고 대신 비공개 지원 문구와 정적 도움 안내를 보여준다. 벌점·자동 상담 전달·응답 보장을 안내하지 않는다. 지원 기능을 이해하지 못하는 구버전 화면은 업데이트를 요구한다. 예외 화면·capability 헤더를 구현했고 정상 접수 완료 카드 정책은 유지한다.

## 정상 흐름

**작성 화면 → 보내는 중 버튼 → 기존 완료 카드**로 끝낸다. 별도의 분석·대기·재생 중·재생 완료 화면, 진행 단계 목록, 대기 순번, 예상 시간 카운트다운을 추가하지 않는다. 학생이 전광판 재생이 끝날 때까지 휴대폰을 켜 둘 필요도 없다.

접수 응답 202를 받거나 같은 요청의 영수증을 확인하면 바로 완료 카드를 보여준다. 이 완료는 글을 안전하게 보냈다는 의미다. 전송 결과가 불명확할 때에는 성공으로 표시하지 않고 같은 요청을 뒤에서 확인한다.

## 기존 완료 카드에서 바꿀 부분

| 요소 | 현재 시안 | 변경안 |
| --- | --- | --- |
| 제목 | 전광판에 곧 올라가요! | **메시지를 보냈어요!** |
| 설명 | 약 1분 동안 화면 가득 보여요. 고개를 들어 전광판을 봐주세요. | 확인 후 전광판에 순서대로 올라가요. 표시되면 15초 동안 크게 보여요. |
| 대기 안내 카드 | 다른 멘션이 띄워지는 중이면 잠깐 기다렸다가 순서대로 올라가요. | 기존 위치·디자인 유지. 필요하면 앞선 메시지가 있으면 잠시 기다릴 수 있어요. |
| 메시지 미리보기 | 작성한 글 | 기존 미리보기 유지 |
| 버튼 | 하나 더 쓰기 | 유지 |
| 횟수 | 오늘 남은 횟수 1/2 | 서버 usage에 따른 최근 1시간 남은 횟수 |

색상·캐릭터·여백·글 미리보기·버튼 배치는 유지한다. 학생의 배경 이모지 선택을 제거하는 부분과 1분을 15초로 바꾸는 부분은 다음 기능 정책에 필요한 변경이다. 팀 원본 HTML은 참고 자료로 보존한다.

‘메시지를 보냈어요’는 접수 성공 시점에 사용할 수 있다. ‘전광판에 표시됐어요’는 실제 표시를 확인하기 전에는 쓰지 않는다. ‘곧’이라는 시간 약속도 대기 상황에 따라 맞지 않을 수 있어 제목에서 뺀다. 설명의 ‘확인 후’가 게시 전 내용을 확인한다는 최소한의 안내다. 확정된 검수 거절을 성공 카드로 새로 표시하지 않는다.

## 내부 상태와 화면의 연결

| 서버·클라이언트 상태 | 학생이 보는 화면 |
| --- | --- |
| SENDING | 작성 화면 유지, 전송 버튼에 보내는 중… 표시 |
| PREPARING·WAITING·STARTING·SHOWING·SHOWN | 모두 같은 완료 카드. 상태 변화로 문구·화면을 계속 바꾸지 않음 |
| 잠깐의 UNKNOWN | 보내는 중…을 유지하며 동일 요청 확인. 실패·성공을 단정하지 않음 |
| 확인 재시도 한도 초과 | 같은 위치에 전송 결과를 확인하지 못했어요. 와 다시 확인 버튼 |
| NEEDS_REWRITE | 기존 경고 카드에 표현을 조금 바꿔서 다시 보내 주세요. 와 수정하기 버튼 |
| 게시 전 최종 기술 실패·만료 | 같은 완료 카드에 표시하지 못했어요. 잠시 후 다시 보내 주세요. 와 다시 쓰기 버튼 |
| 작성 횟수·정지·입장권 제한 | 기존 제한·경고 화면 재사용, 필요한 시간 또는 QR 재접속 안내만 표시 |
| PLAYBACK_UNCONFIRMED | 완료 카드 유지. 운영 복구 대상으로 처리하고 학생에게 재전송을 요구하지 않음 |
| contentStatus = PURGED | 별도 화면·팝업 없음. 이미 표시한 완료 카드 유지 |

표시 상태 조회가 잠깐 실패한 것은 글의 실패가 아니다. 이미 보여준 완료 카드를 바로 오류 화면으로 바꾸지 않는다. 실제로 게시 전에 실패·거절·만료가 확정됐을 때만 학생이 할 수 있는 행동을 안내한다. 플레이백 토큰·큐·모델 오류·ACK 같은 내부 용어는 표시하지 않는다.

‘하나 더 쓰기’는 기존 버튼을 유지하되 서버의 남은 횟수·접수 간격·처리 중 제한에 맞춰 활성화한다. 아직 보낼 수 없다면 잠시 후 다시 보낼 수 있어요. 정도만 표시한다. 제한 시간이 길다면 서버가 준 다음 작성 가능 시각만 보여주고 이유별 기술 설명은 하지 않는다.

## 완료 뒤 문제가 생기는 경우

완료 카드가 열려 있을 때만 뒤에서 해당 접수 상태를 확인한다. 검수와 배경 준비는 서버에서 계속 진행하며, 준비 순서와 15초 재생도 휴대폰 화면과 무관하다. 정상적인 내부 단계 변화는 학생에게 알리지 않는다.

검수 거절이나 게시 전 최종 실패가 확인되면 같은 카드의 짧은 안내와 버튼만 바꾼다. 다른 글을 작성 중이라면 그 입력 내용을 덮거나 강제로 화면을 이동하지 않는다. 이때 한 번의 짧은 배너로 이전 글의 수정 필요를 알리는 정도로 제한한다. 이미 확인한 오류를 반복 팝업으로 띄우지 않는다.

탭을 닫거나 다른 페이지로 이동하면 그 화면의 조회를 종료한다. 최초 버전에서는 푸시·이메일·결과 이력 화면을 추가하지 않는다. 따라서 탭을 닫은 뒤 발생한 거절·실패를 별도로 전달하는 것은 보장하지 않는다. 서버는 영수증을 보관하므로 같은 완료 화면을 다시 열었을 때에는 결과를 확인할 수 있다.

뒤에서 재시도하더라도 같은 멱등 키를 유지한다. UNKNOWN이나 재생 완료 보고 유실을 이유로 새 글을 자동 작성하지 않는다. 학생의 새 키 제출은 수정·다시 쓰기를 명시적으로 선택한 경우에만 한다.

## 다른 절충안과 선택 이유

검수·배경 준비가 끝난 뒤 완료를 보여주면 작성 규칙 거절을 먼저 안내할 수 있다. 다만 모델 지연이나 배경 준비 동안 로딩이 길어지고, 120초 준비 기한까지 휴대폰이 기다려야 할 수도 있다. 현재의 간단한 시안에는 **접수 확인 후 바로 완료 카드, 확정된 문제만 추가 안내**가 맞는다.

이 선택으로 내부의 세밀한 상태·오류·복구 검증을 없애지는 않는다. 상태를 화면에 모두 노출하지 않는 것이다. 첫 프레임과 15초 완료 확인은 전광판 앱과 서버 사이에서 계속 관리한다.

## 프론트 수락 기준

- 정상 전송은 현재 시안의 완료 카드 한 개로 끝나고 내부 상태가 바뀔 때마다 화면을 전환하지 않는다.
- 202를 받기 전 전송 성공을 표시하지 않는다. UNKNOWN 복구 후에도 중복 접수하지 않는다.
- 검수 거절·게시 전 최종 실패만 짧게 안내하고 수정·다시 쓰기 동작을 제공한다.
- 다른 글 작성 중 도착한 이전 결과가 현재 입력과 화면을 덮지 않는다.
- 오래 걸리는 정상 대기를 실패로 오인하거나 표시 완료로 단정하지 않는다.
- 성공·오류 메시지는 스크린리더로도 알 수 있게 하고, 불필요한 포커스 이동·반복 알림은 만들지 않는다. [W3C 상태 메시지 안내](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)를 참고한다.
