# 현재 구현 상태와 남은 수락

기준일: 2026-11-03. 현재 저장소에는 백엔드 애플리케이션과 실제 학생 모델 v0의 개발용 연결 코드가 있다. 이전 설계 문서의 “구현 전” 문구는 작성 당시의 상태이며, 현재 코드·실행 증거는 이 문서와 실제 소스를 확인한다. **설계 가지 102개 전체의 완료·학생 대상 출시 가능·ASVS 전체 준수를 선언하는 문서가 아니다.**

- 학생 작성·QR 스캔 처리·전광판·운영자 React 화면과 애니메이션. 현재 API 실행은 전광판 웹 화면이 자동으로 생긴다는 뜻이 아니다.
- 실제 AI의 독립 평가·게시 허용 기준·목표 서버의 CPU/RSS 측정. 기본 어댑터는 개발용 fake이며, 로컬 학생 모델 v0의 실제 추론·해시 manifest·검토 필요 결과 연결은 추가했다. [모델 연결 현황](student-model-integration.md)
- 검토·확장한 운영용 금칙 사전과 양성/음성 평가. 시작 사전은 production에서 차단한다.
- 클라우드 공급자·자원·공개 도메인·DNS·HTTPS·학교망·실제 노트북/패널 지속 시험. 로컬 Compose는 localhost용이다.
- 운영 로그의 14일 보관·외부 백업·격리 복원 sanitize·복원 훈련. DB 보관 정리와 큐 종료 작업 정리는 구현했지만 실제 운영 스케줄·모니터링·백업은 별도 설정이 필요하다.
- 운영자 담당·학교의 공개/보관 안내·허용 유실 폭·이의 처리·실제 모델과 시스템의 출시 수락.

실제 챗봇 UI·모델·외부 프로그램 연동은 첫 범위에서 제외한다. CHATBOT enum·mode API의 렌더 전환 계약은 예약되어 있지만 실제 챗봇이 없다는 이유로 독립 무드월 개발을 기다리지 않는다. 멘션 검수 AI는 별개로 필수 연결 대상이다.

## 최신 변경: AI 팀 자료와 진단 도구 통합

AI 팀 자료를 `ai/train`, `ai/data`, `ai/tools/local_api`로 정리했다. 노트북·CSV는 원래 Git blob을 그대로 보존하며 CSV 줄바꿈의 자동 변환도 방지한다. 루트 README는 전체 프로젝트를 안내하고 학습·진단 설명은 [AI 가이드](../ai/README.md)로 연결한다.

로컬 진단 API는 127.0.0.1:8001을 사용하고 실제 서비스의 해시·라벨·완전한 가중치 검증 로더를 재사용한다. 요청을 자르지 않고 30 grapheme·원문 UTF-8 2048바이트·JSON 본문 4096바이트를 구분해 검사한다. 시작 시 한 번 로드하며 응답에는 진단용·게시 권한 없음 표시가 있다. 학습용 노트북의 탐색 임계값을 서비스 승인 기준으로 사용하지 않는다.

torch 없는 Linux Docker의 진단 API 회귀 19개와 Ruff가 로컬에서 통과했다. 네트워크를 끄고 실제 모델·소스를 읽기 전용으로 마운트한 HTTP smoke도 통과했다. 기본 모델 경로·health·30 grapheme 원문 보존·실제 분류 응답·31 grapheme 및 잘못된 Unicode 거절을 확인했다. 이는 AI 정확도·안전성 평가나 React 화면·공개 배포 수락이 아니다. CI는 AI 도구 회귀와 함께 백엔드·AI·시안·전광판 README의 링크도 검사한다. 원본 학습 노트북은 내용을 보존하고 새 도구의 정적 검사와 구분한다.

## 이전 변경: 병합 전 검수 보완

2026-11-03 병합 검수에서 발견한 전광판 지연 응답·모델 bundle 식별·교체 설정을 보완했다. 전광판 페이지 요청은 5초 안에 완료해야 하며 실제 abort와 인증 세대를 함께 검사한다. 수신 시각에는 전체 RTT를 보수적으로 반영해 만료된 온라인 허가나 이전 날짜를 되살리지 않는다. 지연·재접속·자정·1시간·늦은 인증 오류를 포함한 Node 검사 34개가 로컬에서 통과했다. 네트워크 상태에 따라 5초 미만으로 화면 경계가 앞당겨질 수 있으며 DB 보관 기한은 그대로다.

새 bundle 버전은 가중치뿐 아니라 설정·토크나이저를 포함한 4개 artifact 해시 전체로 만든다. 이미 공개한 v0 릴리스는 파일·버전을 보존하고 정확히 같은 기존 bundle의 준비 재실행도 지원한다. 준비 도구 검사는 Windows에서 40개 통과·symlink 권한 검사 3개 생략이다. Compose에서 bundle 폴더와 버전을 함께 지정할 수 있게 했고 합성 설정으로 기본·다른 경로의 일치를 확인했다. 운영용 모델 예시는 현재 v0 전용 어댑터와 구분했다.

CI는 문서·AI 경로 변경도 포함하며 OpenAPI·SQL 문법·문서 링크·AI 계약 검사와 AI 진단 API 검사를 추가했다. AI 검사는 해당 코드가 저장소에 있을 때 실행한다. 원격 실행·병합 상태는 PR·Actions를 기준으로 확인한다. HTML 원본은 참고 시안으로 보존하고 실제 프론트에 적용할 QR·입력·이모지·비동기 결과·애니메이션 차이를 [연결 안내](../prototypes/README.md)에 명시했다.

## 이전 변경: 실제 학생 모델 v0 개발 연결

2026-11-03 실제 로컬 가중치를 CPU 추론 어댑터에 연결했다. Linux 모델 이미지·PostgreSQL 16 격리 DB의 백엔드 전체 **348개 통과(225.01초)**를 확인했다. 실제 작업자가 모델을 로드하고 READY를 등록한 뒤 큐의 글을 소비해 `NEEDS_REWRITE`로 저장하고 정상 종료하는 검사도 포함한다. torch가 없는 기본 CI 이미지에서는 새 어댑터·bundle·계약 검사 **99개 통과**를 확인했다. Windows 실모델 포함 검사는 99개 통과·symlink 권한 검사 3개 생략이다. 실행 방법·고정 버전·관찰한 오탐·측정 범위는 [모델 연결 기록](student-model-integration.md)에 있다. 이 수치는 로컬 검증이며 원격 PR의 새 CI 실행 결과가 아니다.

v0는 평가된 허용 경계가 없어 항상 `UNCERTAIN`을 반환하며, production 로딩을 거절한다. React 화면 연결·공개 운영 수락과 구분한다. 아래 10월 29일 수치는 이전 변경의 이력이다.

## 이전 변경: 강조·4개 제한 없이 일반 말풍선

현재 정책은 **승인 즉시 일반 떠다니는 말풍선 → 접수 1시간에 DB 원문 삭제·받은 내용은 투명 말풍선 → 다음 KST 자정 정리**다. 강조 슬롯·남은 강조 시간·승인 표시 대기·DISPLAY_BUSY를 제거했다. OpenAPI 0.7.0은 `bubbles`의 100개 전송 페이지, `snapshotAt`·`bubbleTotalCount`·`nextCursor`, 카드의 `acceptedAt`을 제공한다. 100개는 표시 상한이 아니며 매 동기화에서 첫 페이지부터 끝까지 수집한다. 현재 schema head는 `0005_floating_bubbles`다. [전체 흐름](service-flow.md)을 따른다.

이번 변경의 실행 결과는 아래와 같다. 아래 251개·13개 등의 수치는 변경 전 이력이며 새 정책 검증을 대신하지 않는다. 독립 캐시·페이지 동기화 모듈의 시험은 실제 React 화면·브라우저·전광판 현장 시험과 구분한다.

- Python 3.12·격리된 Windows PostgreSQL 17.8에서 전체 회귀 **254개 통과, Linux 전용 3개 skip**. 105개 승인 글의 100+5 전체 페이지 전달, 중단·오프라인 중 동기화, 표시 대기 한도 제거, 숨김·원문 만료·커서 위조·자정·기기 세대와 기존 접수·제재를 확인했다. PostgreSQL 16/Linux 전체 실행은 CI에서 별도로 확인해야 한다.
- Node 24.11.0에서 전광판 모듈 **25개 통과**. 일반 말풍선 전체 반환, 1시간 뒤 같은 내용의 투명 전환, 전체 페이지 수집, 중복 병합, 만료 커서 재시작, 인증 변경·늦은 응답 차단, 새로고침 복원과 자정 정리를 확인했다. 실제 React 화면과 브라우저 영구 저장의 통합 시험은 남아 있다.
- 빈 DB에 `0005_floating_bubbles`까지 실제 적용했다. 구버전의 대기·강조·투명 행을 새 일반 말풍선 상태로 옮기고, 숨김·만료 행과 원문 보관 시각을 보존하며, 슬롯 열과 관련 인덱스를 제거하는 실제 SQL 회귀가 통과했다. 과거 기간 변경 시험은 별도 스키마에서 롤백하므로 현재 head를 바꾸지 않는다.
- 실제 DB 제약 회귀 SQL에서 이름이 지정된 제약 거절 34개와 rolling·숨김·규칙·감사 단언 8개를 확인하고 시험 데이터를 롤백했다. Ruff check·format도 통과했다. 문서 검증기는 OpenAPI 0.7.0·27개 경로·195개 응답 예시·43개 DDL·254개 로컬 링크·HTTP DTO 유효 7개/거절 21개를 확인했다.

## 이전 정책 이력: DB 삭제 뒤 당일 투명 말풍선 유지

아래 버전의 정책은 **강조 목표 1시간, 서버 DB 원문·제출 행은 접수 후 1시간에 삭제, 전광판이 받은 글은 내용 담긴 투명 말풍선으로 다음 KST 자정까지 유지**다. 서버 DB 삭제와 화면 말풍선 삭제를 같게 처리한 직전 설명을 정정했다. OpenAPI 0.6.0은 카드와 state의 `ambientUntil`, state의 `removedIds`·`cacheResetToken`·`deviceGeneration`으로 두 수명과 명시적 숨김을 분리한다. 상세 흐름은 [쉬운 설명](service-flow.md)을 따른다.

이번 정정의 실행 검증은 아래 과거 226개 결과와 구분해 기록한다. [당일 말풍선 모듈](../clients/display/bubble-cache.mjs)은 외부 패키지 없이 당일 localStorage·메모리 fallback·내용 담긴 투명 전환·숨김·자정 정리를 제공한다. React 화면 전체·실제 전광판과 localStorage의 브라우저 통합 시험은 별도 연결 범위다.

- Python 3.12·격리된 Windows PostgreSQL 17.8에서 전체 회귀 **251개 통과, Linux 전용 3개 skip**. DB 삭제 후 숨김·당일 숨김 목록·기기 세대·API 계약과 기존 접수·검수·보관 경계를 함께 확인했다. 이번 변경의 PostgreSQL 16/Linux 전체 실행은 CI에서 별도로 확인해야 한다.
- Node 24.11.0에서 전광판 캐시 시험 **13개 통과**. 1시간 경계의 내용 유지·빈 서버 목록·인증 후 새로고침 복원·자정 정리·명시적 숨김·기기 교체·통신 단절·저장 실패·40개 순환·늦은 응답의 타이머 역행 방지를 확인했다. 저장소를 주입한 단위 시험이며 실제 브라우저 통합 시험은 아니다.
- 회귀 중 발견한 시작 연결 대기와 실패 정리를 수정했다. DB는 시작 시 연결 1개를 최대 10초에 확보하고 요청 연결 대기는 500ms를 유지한다. 큐 시작·종료 실패에도 DB를 닫으며 테스트 fixture도 시작 실패를 정리한다. 과거 migration 모듈은 DDL 트랜잭션 전에 불러와 5초 유휴 제한과 충돌하지 않게 했다.
- 문서 검증기는 OpenAPI 3.1·27개 경로·194개 응답 예시·44개 DDL·252개 로컬 링크·HTTP DTO 7개 유효/20개 거절 fixture를 통과했다. 이후 문서 링크 추가는 최종 검증 결과를 우선한다.

## 정정 전 1시간 강조·삭제 정책의 실행 이력

아래는 DB 삭제와 화면 종료를 같게 해석했던 직전 버전의 결과다. 해당 226개 통과는 새 투명 말풍선 캐시의 검증 결과가 아니다.

- Python 3.12·격리된 Windows PostgreSQL 17.8에서 최종 전체 회귀 **226개 통과, Linux 전용 3개 skip**. Linux supervisor 코드는 이번 정책 변경에서 수정하지 않았으며 PostgreSQL 16/Linux 전체 실행은 CI에서 확인할 범위다.
- 접수 1시간 직전 조회 가능·정확한 경계부터 본인 조회 404/운영자 목록 제외, 모든 검수 상태의 물리 삭제, 일일 제재·최근 60분 쿼터 보존을 실제 DB에서 확인했다.
- 10분 뒤에도 강조 유지·1시간 경계 직접 만료·투명 단계 미생성, pause/offline/대기 수명 미연장, 슬롯 회수, 삭제 뒤 revision 알림과 잠금 순서를 검증했다.
- `0004_spotlight_1h`를 실제 적용했다. 과거 0002와 새 0004의 실제 SQL 회귀는 시험 트랜잭션을 롤백하여 현재 schema를 보존한다. 기본값은 3600000ms다.
- OpenAPI 0.5.0의 만료 필드와 응답 계약, Ruff check/format, 문서 검증기 246개 로컬 링크·194개 응답 예시를 확인했다. 기존 193개와 벤치마크는 아래의 과거 정책 이력이다.

이전 버전의 4슬롯·시간당 약 4개 명목 용량과 대기 중 만료 문제는 현재 일반 말풍선 정책에서 제거했다.

## 이전 코드 검수의 실행 증거

**이후 정책 변경:** 원문·제출과 멱등 응답 보장은 접수 후 1시간이고 승인 즉시 일반 말풍선이 된다. 받은 내용은 1시간 뒤 투명 말풍선으로 다음 KST 자정까지 남는다. 아래 193개·130개는 변경 전 이력이며 현재 검증을 대신하지 않는다. [전체 흐름](service-flow.md)과 OpenAPI 0.7.0을 현재 계약으로 본다.

2026-10-29 실제 소스를 다시 검수하고 DB·인증·작업자를 수정했다. 상세 변경과 공식 근거는 [검수 기록](standards-review.md), 원시 지표는 [DB 실행 계획 요약](checks/db-plan-2026-10-29.json)에 있다.

- Python 3.12·격리된 Windows PostgreSQL 17.8에서 전체 회귀 193개 통과, Linux 전용 3개는 OS 조건으로 skip했다. 운영 대상 PostgreSQL 16/Linux 전체 묶음의 이번 변경 후 재실행은 CI에서 별도로 확인해야 한다.
- Ubuntu WSL에서는 실제 worker 종료 함수를 AST로 불러온 표준 라이브러리 harness로 두 프로세스 그룹 시나리오를 실행했다. leader가 이미 종료된 경우와 TERM 후 종료된 경우 모두 TERM을 무시하는 helper까지 KILL·reap되고 PGID가 사라졌다. 이는 전체 Linux/DB worker 통합 시험을 재실행한 결과와 구분한다.
- 합성 멘션 10000개로 EXPLAIN ANALYZE·BUFFERS를 비교했다. 최종 쿼리는 offset 0·5000·9960 모두 인덱스에서 ID를 고른 후 PK로 원문 40개만 가져왔다. 진단에서 임시로 제거한 인덱스의 복구와 생성 데이터 정리를 확인했다. 수치는 로컬·캐시 영향이 있는 단일 측정이며 SLA가 아니다.
- wheel을 실제 빌드·해제하고 저장소 밖 cwd에서 기본 사전·OpenAPI·migration 3개와 head를 확인했다. 필수 자산 8개의 원본 바이트가 보존되었다.
- Ruff check·format 통과. 인증 성공·실패/권한·CSRF·요청 제한은 원문과 비밀을 제외한 제한된 JSON 로그로 연결했다. 상세 로그 상한을 넘긴 집계는 다음 요청 때 기록하므로 완전한 전건 감사나 ASVS 인증을 주장하지 않는다.
- 실제 PostgreSQL에서 제약 회귀 SQL도 실행해 지정한 이름의 제약 거절 34개와 rolling/숨김/규칙/감사 단언 8개를 확인하고 fixture를 롤백했다. 최종 DB 경계 회귀 7개도 추가 재실행해 통과했다.

## 초기 구현의 실행 증거

Python 3.12·PostgreSQL 16·Linux Docker에서 실행했다. 예전 설계 명세·DDL 검사 결과는 [검증 기록](verification.md)에 별도로 남아 있다. 실제 학생 원문과 운영 DB는 사용하지 않았다.

강조 시간은 10분(600000ms) 기준으로 다시 검증했다. 종료 후 당일 AMBIENT 유지·pause·오프라인·자정 정책을 시험했고, 실제 0002 upgrade SQL로 대기 카드 600000ms·진행 중 카드의 남은 시간 연장·기존 AMBIENT 미복원을 확인했다. 초기 0001은 기존 1분 baseline으로 보존하며 당시 schema head는 말풍선 정렬 인덱스를 추가한 `0003_ambient_order`였다. 최신 head와 1시간 강조 migration의 검증은 아래 이후 정책 기록을 우선한다.
