# 무드월 화면 시안 원본

**실제 서버에 연결한 화면은 [frontend](../frontend/README.md)에 있다.** [v2 로컬 구현](../docs/playback-local-implementation.md), [15초 재생](../docs/playback-design.md), [접수 상태와 오류](../docs/submission-status-errors.md)를 따라 학생·전광판·운영자 React 화면을 연결했다. 원본의 60초 진행바는 15초 재생으로 바꾸고 학생 이모지 선택 대신 감정 테마를 사용한다.

학생 화면은 [최소 변경안](../docs/student-ux.md)을 따른다. 기존 완료 카드의 배치·미리보기·하나 더 쓰기 버튼은 유지하고 제목은 메시지를 보냈어요!, 설명은 확인 후 순서대로 표시·15초 안내로 바꾼다. 상세 분석·대기·재생 상태 화면을 추가하지 않는다.

[moodwall-display.html](moodwall-display.html)은 팀에서 전달받은 HTML을 변경 없이 보관한 파일이다. 전광판·새 멘션 풀스크린·모바일 작성·전송 완료·필터 경고·작성 제한의 6개 시안을 한 문서에 담고 있다. 압축 자산을 내장한 전용 런타임 형식이며, 일반 React 프로젝트의 컴포넌트 소스는 아니다.

원본 HTML 안의 입력·이모지 선택·전송 완료 전환은 로컬 데모이며 실제 서버에 글을 보내지 않는다. QR은 자리표시자이고 말풍선·통계도 합성 샘플이다. React는 이 원본의 크림색·파란색·작성/완료 카드·글 미리보기를 참고했고 원본 파일은 변경하지 않았다. `file://` 시안에 운영 API를 직접 연결하지 않는다.

| 화면 | 실제 React 경로 | 현재 연결 |
| --- | --- | --- |
| 학생 작성·완료 | `/`, `/student`, `/join#ticket=…` | QR 입장·익명 세션·본문만 전송·접수 영수증·간단한 완료/오류 안내 |
| 전광판 | `/display` | 장치 등록·실제 QR·감정 테마·15초 재생·당일 말풍선·숨김·재연결 |
| 운영자 | `/operator` | 로그인·장치 등록 코드·접수/화면 제어·일반/투명 말풍선 숨김 |

원본과 실제 화면의 기능 차이는 다음과 같다.

- 시안의 하루 2회 제한 대신 서버의 최근 60분 3회 한도를 표시한다.
- 1분 풀스크린 대신 준비 완료 순서로 한 글씩 최소 15초 표시한다. 다른 글은 현재 재생을 중단하지 않고 기다린다. 기존의 4개 강조 슬롯은 없다.
- 원문 보관 기한은 접수 시각이 아니라 **최초 표시 시작 승인 +1시간**이다. 서버 원문이 사라져도 이미 받은 같은 내용은 투명 말풍선으로 다음 KST 자정까지 남는다. 자정·명시적 숨김·기기 해지에는 당일 캐시도 정리한다.
- 글자 수는 UTF-16 길이 대신 서버와 같은 grapheme 기준을 사용한다.
- 실제 QR·페어링·heartbeat·SSE·재접속·운영자 숨김 처리를 연결했다.

학생은 배경 이모지를 고르지 않고 본문만 `POST /api/v2/submissions`에 보낸다. AI 결과의 `sceneId`와 고정된 테마/CSS/SVG 효과를 연결하며 AI 이미지 생성은 구현하지 않는다. `Intl.Segmenter('ko', { granularity: 'grapheme' })`로 글자 수를 표시하고 서버의 NFC·공백·제어문자 검사를 최종 기준으로 삼는다.

`/join#ticket=…`은 실제 입장 라우트다. ticket을 읽은 뒤 주소에서 제거하고 학생 세션·QR 교환·CSRF를 연결한다. 새로운 제출에는 UUID `Idempotency-Key`를 사용하고 네트워크 오류로 같은 요청을 다시 보내면 키와 본문을 유지한다. `202`나 기존 영수증으로 접수를 확인하면 메시지를 보냈어요! 카드 한 개를 보여준다. `/api/v2/submissions/{id}`를 뒤에서 조회하되 정상 검수·대기·재생 단계는 추가 화면으로 노출하지 않고 확정된 수정 필요·실패만 짧게 안내한다. 최근 60분 횟수와 재시도 시각은 세션의 `usage`와 `/api/me/usage`를 사용한다. API와 프론트는 같은 origin으로 제공한다.

전광판은 v2 재생 컨트롤러의 자산 준비·첫 프레임·완료 확인·단일 재생 소유권을 React 렌더러에 연결했다. 장치 등록 후 visible일 때 heartbeat를 보내고 SSE 알림 또는 주기 동기화로 `/api/v2/display/state`의 모든 페이지를 읽는다. SSE에 글 본문이 담겼다고 가정하지 않는다. 페이지 수집·인증 변경·당일 캐시는 독립 런타임을 사용한다.

감정 표시명과 효과는 서버의 `emotion`·`animationId`·`sceneId`로 매핑한다. 시안의 한글 감정명·`confetti`·`sparkle`을 그대로 서버 코드로 쓰지 않는다. 효과 ID는 `fireworks`, `hearts`, `sparkles`, `petals`, `clouds`, `rain`, `embers`, `float`다. React의 기분 날씨·감정 비율은 이 노트북의 당일 캐시에 남은 글 기준이라고 표시한다. 전체 학교의 공식 통계나 서버 영구 집계가 아니다. 서버 `bubbleTotalCount`는 그 시점 서버에서 공급 가능한 원문 수다.

v1의 `emojiId`·즉시 일반 말풍선·접수 기준 1시간 API와 캐시 모듈은 이전 화면의 호환 경로다. 새 React 화면은 v2를 사용한다.

실행은 [프론트 가이드](../frontend/README.md), 연결 기준은 [HTTP 계약](../docs/openapi.json), [전체 흐름](../docs/service-flow.md), [전광판 캐시 모듈](../clients/display/README.md)이다. 모델 파일과 실행 방법은 [AI 모델 연결 가이드](../docs/student-model-integration.md)를 따른다. 실제 브라우저·휴대폰·HDMI 패널 현장 시험은 별도 수락 대상이다.
